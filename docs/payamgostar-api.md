# API واسط پیام‌گستر برای داشبورد فرین

این سرویس **ساخته شده ولی به CRM واقعی متصل یا روی سرور منتشر نشده است**. سایت GitHub Pages همچنان با داده‌های فرضی کار می‌کند. کد API روی یک میزبان Node.js جدا اجرا می‌شود؛ GitHub Pages قادر به اجرای آن نیست.

## راه‌اندازی روی سرور

Node.js نسخه ۲۲٫۹ یا جدیدتر لازم است. تنها وابستگی مستقیم، `fast-xml-parser` برای پردازش معتبر پاسخ XML است.

```sh
npm ci --ignore-scripts
cp .env.example .env
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

توکن تولیدشده را در `FARIN_API_TOKEN` فایل `.env` ذخیره کنید. از توکن نمونه یا رمز کاربر CRM به جای آن استفاده نکنید. فایل `.env` در git نادیده گرفته می‌شود و باید فقط روی میزبان سرویس، با دسترسی محدود، قرار بگیرد. رمز و توکن واقعی را در گفتگو، فایل نمونه، کد مرورگر، عکس یا گیت‌هاب نگذارید.

سپس این تنظیمات را روی سرور تکمیل کنید:

- `PAYAMGOSTAR_BASE_URL=https://farinroshan.cloud.payamgostar.com`
- `PAYAMGOSTAR_USERNAME` و `PAYAMGOSTAR_PASSWORD`: کاربر سرویس با دسترسی **فقط‌خواندنی** به مراکز حقوقی، فاکتورهای فروش و فرصت‌های موردنیاز.
- `PAYAMGOSTAR_CURRENCY`: پس از بررسی واحد واقعی CRM، `IRR` برای ریال یا `IRT` برای تومان. هیچ واحدی حدس زده نمی‌شود.
- کلید نوع موجودیت برای هر بخش، در صورت نیاز به محدودکردن مراکز و فرم‌های شرکت.
- نگاشت شناسه محصولات و مراحل CRM، مطابق توضیح زیر.

```sh
npm run start:api
```

بدون اطلاعات CRM، سرویس با توکن معتبر بالا می‌آید، مسیر وضعیت `not-configured` نشان می‌دهد و مسیرهای داده پاسخ ۵۰۳ می‌دهند. وجود اطلاعات تنظیم‌شده به معنی صحت رمز یا تأیید اتصال نیست: وضعیت `configured-unverified` می‌شود. نخستین دریافت موفق داده، اتصال را برای همان درخواست تأیید می‌کند.

میزبان پیش‌فرض `127.0.0.1:8787` است. در انتشار واقعی، سرویس پشت reverse proxy با **HTTPS** و مدیریت فرایند اجرا شود. توکن API فعلی برای فراخوانی از سرویس‌های قابل اعتماد و تست اتصال است؛ برای وصل‌کردن مستقیم داشبورد عمومی باید ابتدا ورود کاربران و دسترسی مبتنی بر جلسه یا توکن کوتاه‌عمر پیاده‌سازی شود. توکن ثابت سرور نباید در JavaScript داشبورد قرار بگیرد. CORS به‌تنهایی احراز هویت نیست.

تعریف مسیرها برای ابزارهای توسعه: [OpenAPI](openapi.json).

## مسیرها

همه پاسخ‌ها JSON با `Cache-Control: no-store` هستند. تنها مسیر عمومی `GET /healthz` است و فقط `{ "ok": true }` برمی‌گرداند.

| مسیر GET | خروجی |
| --- | --- |
| `/api/v1/status` | وضعیت تنظیمات؛ بدون تست شبکه یا نمایش رمز؛ Power BI قطع است |
| `/api/v1/dashboard` | مراکز فعال، سفارش‌ها، فرصت‌ها، خلاصه محاسبات و کیفیت نگاشت |
| `/api/v1/customers` | مراکز دارای سفارش یا فرصت در فیلتر انتخاب‌شده؛ صفحه‌بندی |
| `/api/v1/orders` | فاکتورهای فروش مرتبط با مراکز حقوقی؛ صفحه‌بندی |
| `/api/v1/opportunities` | فرصت‌های مرتبط با مراکز حقوقی؛ صفحه‌بندی |

تمام مسیرهای `/api/v1/` نیاز به هدر زیر دارند:

```http
Authorization: Bearer <FARIN_API_TOKEN>
```

تمام مسیرهای داده نیاز به تاریخ **میلادی** دارند:

```http
GET /api/v1/dashboard?from=2026-09-01&to=2026-09-30&service=all
```

- `from` و `to`: روزهای واقعی به شکل `YYYY-MM-DD`، شامل روز پایان؛ حداکثر ۳۶۶ روز. تاریخ‌ها مطابق روز ثبت‌شده در CRM پردازش می‌شوند؛ تبدیل تاریخ شمسی در لایه رابط کاربر انجام خواهد شد.
- `service`: `all`، `implant`، `guide`، `ortho`، `cosmetic`، `mixed` یا `unmapped`.
- `search`: جست‌وجوی نام مرکز یا شهر، حداکثر ۱۰۰ نویسه. تمام سفارش‌ها، فرصت‌ها و مجموع‌ها با این جست‌وجو محدود می‌شوند.
- `page` و `pageSize`: برای فهرست‌ها؛ پیش‌فرض ۱ و ۵۰، حداکثر اندازه ۲۰۰. خلاصه از کل داده فیلترشده محاسبه می‌شود و مستقل از صفحه‌بندی است.

هیچ URL، نام عملیات، query خام CRM یا رمز از پارامتر درخواست پذیرفته نمی‌شود. درخواست تغییر داده وجود ندارد. `POST`، `PUT` و `DELETE` پشتیبانی نمی‌شوند؛ درخواست با بدنه نیز رد می‌شود.

## قرارداد داده

`schemaVersion: 1`، `source: "payamgostar"` و `demo: false` تنها پس از دریافت موفق داده ارسال می‌شوند. هیچ جایگزینی خاموش با داده نمایشی وجود ندارد. در خطای CRM، پاسخ خطا بازمی‌گردد.

- `customers`: `id`، `name`، `city`.
- `orders`: `id`، `customerId`، `date`، `service`، `amountToman`، `status`.
- `opportunities`: `id`، `customerId`، `date`، `service`، `amountToman`، `stage`.
- `summary`: تعداد فاکتور، مراکز دارای فاکتور، مبلغ فاکتورهای فروش، ارزش فرصت‌های باز، نرخ برد، سهم مبلغ هر خدمت و جمع ماهانه میلادی.
- `quality`: شمارش رکوردهای اشخاص/هویت‌های خارج از محدوده مراکز حقوقی و خدمات یا مراحل نگاشت‌نشده.
- `definitions`: تعریف صریح مبالغ، تاریخ‌ها و محدوده گزارش.

مبالغ به صورت **رشته اعشاری تومان** ارسال می‌شوند، مانند `"12500.125"`. محاسبات با BigInt و دقت یک‌هزارم تومان انجام می‌شود تا اعشار ریالی و ارقام بزرگ گرد نشوند. `invoiceValueMillionToman` همان جمع است با واحد میلیون تومان. API مبالغ CRM با بیش از دو رقم اعشار را رد می‌کند تا دقت به‌طور خاموش از دست نرود.

«درآمد» در این API در واقع **ارزش نهایی فاکتورهای فروش در همه وضعیت‌ها** از `FinalValue` است، نه وصول نقدی یا درآمد شناسایی‌شده حسابداری. برگشت از فروش، خرید و پیش‌فاکتور در جمع نیستند. قبل از استفاده مالی، وضعیت فاکتورهای تأییدشده و روش کسر برگشت‌ها باید بر اساس فرایند شرکت تعیین شود.

نرخ برد از فرصت‌های `won / (won + lost)` محاسبه می‌شود. مراحل ناشناخته در نرخ برد یا ارزش فرصت باز وارد نمی‌شوند و تعدادشان در `quality` اعلام می‌شود. فرصت باز فقط `lead`، `review` و `proposal` است.

## نگاشت خدمات و مراحل

کلیدهای نگاشت از CRM واقعی استخراج و در تنظیمات خصوصی سرور ذخیره می‌شوند؛ نمونه زیر فقط ساختار را نشان می‌دهد:

```dotenv
PAYAMGOSTAR_PRODUCT_SERVICE_MAP={"00000000-0000-4000-8000-000000000009":"implant"}
PAYAMGOSTAR_STAGE_MAP={"00000000-0000-4000-8000-000000000020":"won"}
```

نگاشت خدمت با **ProductId** ردیف‌های فاکتور یا محصولات فرصت انجام می‌شود. تطبیق حدسی نام محصول وجود ندارد. همه محصولات یک خدمت → همان خدمت؛ چند خدمت شناخته‌شده → `mixed`؛ محصول نامشخص یا نبود محصولات → `unmapped`. مبلغ فاکتور چندخدمتی به شکل حدسی میان خدمات تقسیم نمی‌شود و مجموع همه گروه‌ها دقیقاً با مبلغ کل برابر می‌ماند.

مرحله از `StageId` یا متن دقیق `SaleStage` به مراحل داشبورد نگاشت می‌شود. فیلدهای دلخواه و توضیحات آزاد در خروجی منتشر نمی‌شوند.

## روش اتصال تأییدشده از مستندات

SOAP 1.1 با مسیرهای زیر، namespace `http://tempuri.org/` و SOAPAction مطابق WSDL حساب شرکت:

- `IOrganization.svc`: `SearchOrganization`، سپس `FindOrganizationById`.
- `IInvoice.svc`: `SearchInvoice`، سپس `FindInvoiceById`.
- `IOpportunity.svc`: `SearchOpportunity`، سپس `FindOpportunityById`.

کاربر و رمز در بدنه درخواست **سرور به CRM با HTTPS** قرار می‌گیرند. نام پارامتر `userName` / `username` و پارامتر شناسه هر عملیات از XSD واقعی بررسی شده است. عملیات جست‌وجو ممکن است فقط فیلدهای مشترک را برگرداند؛ به همین علت جزئیات با متد Find خوانده می‌شود. فاکتور و فرصت مرتبط با شخص حقیقی قبل از دریافت جزئیات حذف می‌شود. هیچ متد Save/Delete/Update فراخوانی نمی‌شود.

تعریف سرویس‌های حساب شرکت بدون ورود با GET بررسی شد؛ **درخواست احرازشده یا اطلاعات واقعی هنوز تست نشده است**. سازگاری دسترسی‌ها، واحد مالی، نگاشت‌ها و نتیجه واقعی عملیات باید هنگام راه‌اندازی تأیید شود.

## محدودیت‌ها و آزمون

```sh
npm test
```

تست‌ها احراز هویت HTTP، CORS محدود، محدودسازی نرخ، خطاهای بدون افشای رمز، SOAP واقعی از نظر قالب، آرایه‌های صفر/یک/چندعضوی، شکست سرویس، محدودیت اندازه پاسخ، نگاشت خدمت و مرحله، حذف اطلاعات اضافی، تاریخ‌ها و محاسبه دقیق مبلغ را با داده **ساختگی** بررسی می‌کنند. این تست‌ها وارد حساب واقعی نمی‌شوند.

جست‌وجوهای SOAP صفحه‌بندی upstream ندارند. حداکثر نتیجه هر جست‌وجو پیش‌فرض ۲۰۰ است؛ نتیجه بیش از سقف رد می‌شود و هرگز بی‌صدا کوتاه نمی‌شود. در این حالت بازه تاریخ کوتاه‌تر، کلید نوع موجودیت محدودتر، یا تنظیم سقف با بررسی ظرفیت سرور لازم است. جزئیات با حداکثر ۴ درخواست همزمان در هر گزارش خوانده می‌شوند؛ حداکثر ۴ گزارش همزمان و مهلت کل هر گزارش ۶۰ ثانیه است. هیچ کش یا پایگاه داده دائمی وجود ندارد؛ برای حجم بزرگ باید همگام‌سازی زمان‌بندی‌شده و ذخیره‌سازی محافظت‌شده اضافه شود.

نرخ پیش‌فرض ۶۰ درخواست در دقیقه بر اساس IP واقعی اتصال است. پشت reverse proxy این محدودیت مشترک خواهد بود؛ محدودسازی هر کاربر/IP در proxy نیز تنظیم شود. هدر دلخواه `X-Forwarded-For` مورد اعتماد نیست. پاسخ HTTP از CRM، redirect، DTD، Entity خارجی، پاسخ HTML ورود و قالب ناقص رد می‌شوند. پیام‌های CRM، پاسخ SOAP و رمزها در خطاها یا log چاپ نمی‌شوند.

CORS پیش‌فرض بسته است. در صورت نیاز، تنها origin دقیق HTTPS در `FARIN_ALLOWED_ORIGIN` مجاز می‌شود. این گزینه به معنی اجازه انتشار توکن ثابت یا اطلاعات خصوصی نیست. اتصال UI و ورود کاربران مرحله بعد است؛ گزارش Power BI نیز همچنان متصل نیست.
